# Always Push Changes to GitHub & Vercel Rule

## Mandatory Workflow
Before presenting the final response to the user for any code, asset, or config modifications:
1. Stage all completed changes (`git add .`).
2. Commit with a clear, descriptive message (`git commit -m "..."`).
3. Push to GitHub on the active branch (`git push origin <branch>`).
4. Ensure the changes are pushed and triggering/deployed to Vercel (via GitHub integration connected to Vercel project `prj_A3BZvpjcc4nCf3zTpVTkpN5QcXT6`, or via Vercel CLI).
5. In the final response, provide confirmation of the pushed GitHub commit and Vercel deployment status.
